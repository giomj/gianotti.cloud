Primary data flow — quantum → data lake → web

  1. Quantum → VAST: job results stream from the gateway into VAST D-/C-Nodes over NVMe-oF/RDMA (IPoIB, IPv6), mTLS + workload-identity signed.
  2. VAST → GPU/ML: C-Nodes present the dataset to the ML/AI rack via all-to-all NVMe-oF mounts; no data movement off-fabric.
  3. ML → Gateway: synthesized/inferred results are handed back to the dual-homed gateway for cross-fabric egress.
  4. Gateway → Nutanix: gateway pushes results across the L3 IPv6 boundary (PEP-enforced) into Nutanix AOS storage on the Ethernet fabric.
  5. Nutanix → Internet: K8s-on-AHV webapps/APIs publish the results publicly, egressing through the border PEP/WAF and eBGP edge.

Reference-pod scale: one Quantum Core Pod + one InfiniBand data-lake block + one Ethernet web-front-end block, bordered by one edge pod. In production this unit repeats N× behind additional spine/RR capacity, following Google's Jupiter pattern of horizontally scaling aggregation blocks rather than growing a single spine indefinitely.
